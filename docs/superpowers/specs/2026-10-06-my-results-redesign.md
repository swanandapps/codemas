# My results redesign — 2026-10-06

Approved by the owner from the mockup: https://claude.ai/artifact/YYaMRL8agreBacjxqLQTK3
(light Masai palette only, as in the app). Page: `frontend/src/views/MyResultsView.vue` (student).

## 1. Exam → question → attempt hierarchy
Today attempt rows render as loose cards below each exam card, so it is unclear which exam they belong to.

- Each exam is one container card. It has:
  - a header: an "Exam" eyebrow, the title, the date and question count, and a rank pill;
  - the stats row: questions solved, points, success rate, attempts;
  - the exam summary (AI glow);
  - a **"Questions in this exam · N"** list, joined to the card by a left rail.
- **Question rows** list *every* question in the exam, including unattempted ones. Each row shows the name, a difficulty chip, the attempt count and a status pill:
  - "Passed on attempt N" when passed;
  - "Failed · N attempts" when attempted but never passed;
  - "Not attempted" when there are no attempts.

  The data comes from the exam's questions (the student is enrolled), not only from submissions.
- **Attempt rows** sit inside their question. Each shows the attempt number, language, time, date, and a pass/fail pill with "X of Y tests".
- **Clicks.** Every row with an arrow toggles in place:
  - the exam header shows or hides its body;
  - a question row shows its attempts;
  - an attempt row shows that attempt's tests, code and rubric.

  Hidden tests show "Hidden" for input and expected (behaviour from 2026-10-05). Rows are real `<button>`s with `aria-expanded` and a visible focus ring. Results and rubric load lazily on open, as today.
- **Defaults:** the newest exam is open; the others are collapsed with a one-line summary in the header ("1 / 1 solved · Success rate 50%"); questions are collapsed.
- The owner reported "none of the results tabs are clickable". In testing on 2026-10-06, the existing attempt rows did expand. The new design makes every clickable thing explicit (arrow + hover + focus). When building, verify in the owner's browser that each level opens.

## 4. Weekly recommendation (new)
- **What:** one AI call per student per week. It reads **all of the student's exams together**: per exam the score / available, success rate, rank, attempts per question, questions failed first time and questions still unsolved. It writes:
  - a one-sentence headline;
  - three cards: **Keep doing**, **Work on** and **Next step**. Each has one sentence plus an "evidence" line drawn from the real results.
- **Separate from** the per-exam summary (`backend/ai/tasks.py generate_exam_summary`), which stays.
- **When:** Celery beat, every Monday morning IST, for each student with ≥1 graded exam. It runs on the existing Celery worker, where AI work lives.
- **Storage:** a new model, e.g. `ai.WeeklyRecommendation(student, week_start, headline, cards JSON, input_digest, created_at)`, unique on (student, week_start). If a week's call fails, keep showing the last good one.
- **API:** `GET /api/ai/recommendation/me/` returns the latest one for the requesting student, or 204/empty.
- **UI:**
  - top of My results, above the difficulty tiles, inside AI glow;
  - "Updated Mon, D Mon · next Mon, D Mon";
  - empty state: "Your first weekly recommendation arrives the Monday after your first exam is graded."
- **Prompt rules:**
  - base every claim on the supplied numbers;
  - name questions and topics, not generic advice;
  - no tech or vendor names;
  - keep each card to 1–2 sentences.
- **Cost:** about 98 calls a week at today's seed size. Use the same model and client as the existing AI tasks.
- **Seed and demo:** after deploy, generate one recommendation per seeded student once, via a management command or the task run eagerly, so the demo shows it immediately.
